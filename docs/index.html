任何 agent 讀取來源內容前，原始 PDF／Word 必須先轉成支援的文字；內建 preprocess 可處理 PDF／DOCX，DOCX 先經 bounded、fail-closed OOXML 驗證並附 source-hash provenance。轉換後仍須以 manifest 綁定的精確 bytes 通過 inspect-source-risk。（DOCX 與 GitBook 兩條路徑未經真實來源驗證：十三個 benchmark case 都不是 Word 或 GitBook 來源，證據強度等同 benchmark 的 skipped。）掃描不改寫來源，也不回顯命中 payload；assess-sources --source-risk 會嵌入已驗證 audit，assemble --source-quality 則重新驗證 binding。

DOCX ZIP/XML fallback 的設計改編自 MIT 授權的 virgiliojr94/book-to-skill（固定 revision efda3b2212ce1b2c052126e85e14de40a32442e8）；本專案沒有 runtime dependency，也沒有繼承其 EPUB／RTF／MOBI 支援範圍，並另加上 bounded validation、batch preflight、provenance 與 fail-closed 契約。授權全文見 第三方授權公告。

互動式瀏覽器可顯示的受保護文件能透過 import-rendered-url 離線匯入；版本化 capture provenance 會綁定 original/canonical URL、時間、方法、本機檔案與 SHA-256，只有驗證匹配的 coverage 才會省略該 origin fetch。source-quality reject 也可輸出來源明確連出的 bounded required_source_refs，但不自動 crawl。

Claim-level semantic evidence 會把確定性的 support relationship 連到 exact fragment；選填 v1 evidence[] 會在 run 前重新 materialize、驗證 source identity、locator、digest 與 claim path。沒有 parsed scalar 的 prose 只能支援它精確綁定的單一 claim，OpenAPI derivation 則限 versioned allowlist 並由 Core 重新計算。legacy 相容 shadow run 請查看 core/relationships.json。

Core 保留經測試的 GraphQL／AsyncAPI 純 compiler seam，但在具名下游 consumer 提供真實來源集與驗收契約前，不公開這兩種格式的 CLI 或 run workflow。

GitBook 文件若提供 llms.txt（同樣未經真實來源驗證），可用 deterministic Markdown cache 與 line-cited draft facts 減少模型搬運。scaffold-extraction 可再產生待覆核的 extraction-shaped JSON；先複製並補齊到 workdir，不能直接當成 --extraction，最終仍以來源與驗證為準。

固定產生的 integration-contract.json 會攜帶來源明載的 transport、amount direction、idempotency、line-currency policy 與跨端點 operational 規則；request 沒有 currency 欄位不代表單幣別。validation 也會揭露零實質引用的 supported 來源與空殼 response schema，score 則列出 response 欄位與 hollow operation 指標。

供應商來源仍是 Normative Contract 的唯一權威。被動 feedback workflow 不做 network I/O，可評估 normalized observations、把 proposal／composition 綁定完整 release digest（contract + documentary fragments + support relationships）、保存 immutable candidate inputs；case 可接受一次 non-approval review，只有另一個獨立人工核准後才會發布 immutable exact-scope Effective release，觀察行為不會變成文件支持。Time-aware current lookup 拒絕 query time 早於 approval／composition、expiry、非 current normative base 與 stale pointer／artifact digest，並揭露 validity、open／untested、stale amendment 與 unresolved contradiction counters。同 target 衝突會 fail closed，除非明確的同 scope supersession 保留既有 lineage。全域 current 保持 normative，有限測試也不會被宣稱為普遍「100% 真實」，正式 Provider Erratum 則重走完整 source pipeline。

選填的 --focus 讓提出者在跑之前就宣告「這次串接少了它就不能上線」的東西——結算回呼、錢包轉帳端點、供應商錯誤碼。指令會進入每個擷取 subagent 的 prompt,agent 對每條恰好應答一次:satisfied 的錨點必須釘在精確來源片段上(只給檔名會被拒絕),not_found 必須列出每一份可讀來源。刻意沒有「不適用」這個結局。落空的斷言成為 FOCUS_UNMET 驗證失敗,但產物照常寫出;focus 材料不進 provenance、score 或 Foundry,同一份來源、不同 focus 的兩次 run 仍然可比。

loop-apidoc review 可在本機開啟單使用者工作台，比對 candidate 與 current／baseline，保存結構化 handoff；只有人工明確核准才更新 Foundry current。
